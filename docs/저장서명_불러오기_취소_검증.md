# 저장된 서명 불러오기 · 관리자 서명 취소 · 휴대폰 목록

2026-10-22 기능 추가. 운영 사이트에 배포하지 않은 로컬 변경입니다.

## 사용 흐름

- 처음 직접 작성한 서명은 기존 저장 방식으로 자동 보관합니다. 같은 프로그램의 다음 교육일부터 본인 이름을 누르면 ‘저장된 서명 불러오기’가 활성화됩니다. 누르면 선택한 오늘의 오전/오후/기본 서명에 바로 반영되고 완료 안내를 표시합니다.
- 이전 교육일의 직접 서명 중 취소되지 않은 가장 최근 기록을 사용합니다. 같은 날의 다른 시간, 다른 참여자, 다른 프로그램의 서명은 불러오지 않습니다. 저장 서명이 없으면 버튼은 비활성화되며 직접 서명할 수 있습니다.
- QR 전용 세션은 지정된 날짜·시간만 허용하며, 오전 13시·오후/기본 18시 마감 규칙을 그대로 적용합니다. 미래 날짜나 마감 후 불러오기는 불가능합니다.
- 강사·관리자 → 출결 현황 → 참여자별 출결 → ‘서명 취소’ → 이름·날짜·시간 확인 → ‘서명 취소 확인’. 해당 슬롯을 미서명으로 돌리고 기존 강사 판단도 초기화합니다. 오늘 교육일의 마감 전이면 태블릿/휴대폰에서 다시 서명할 수 있습니다.
- 휴대폰 목록은 번호를 제거하고 32px 이름을 유지합니다. 카드 기본 높이는 112px에서 72px로, 간격은 14px에서 8px로 축소합니다. 긴 이름은 잘리지 않게 줄바꿈합니다.

## 데이터와 권한

- `Signature`에 선택 필드 `sourceSignatureId`, `canceledAt`, `canceledBy`를 추가합니다. 기존 데이터와 호환되며 SQLite 테이블을 새로 만들거나 초기화하지 않습니다.
- 원본 이미지를 매번 복제하지 않고 비공개 파일 참조를 재사용합니다. 불러오기 요청은 프로그램·참여자·대상 날짜·시간·원본 ID를 서버에서 검증하며, 원본 이미지 자체를 휴대폰에 반환하지 않습니다.
- 취소는 관리자만 가능합니다. 태블릿·교육생·QR 세션의 취소 요청은 거절합니다. 서명 취소/불러오기 이벤트는 작업 이력에 이름·날짜·시간과 함께 남습니다.
- 취소된 레코드는 보존하되 현재 명단, 출석 집계, QR 완료 여부, 새 PDF 스냅샷에서 제외합니다. 취소된 서명과 연결된 이미지를 삭제하지 않으므로 과거 PDF 버전은 유지됩니다.
- 취소된 요청 ID를 재전송해도 다시 서명되지 않습니다. 다시 서명할 때는 새 요청 ID를 사용하며, 오래된 취소 요청을 반복해도 새 서명을 취소하지 않습니다.
- 원본을 취소한 경우 이후 불러오기 후보에서 제외합니다. 이미 반영된 다른 교육일의 출결을 연쇄 취소하지는 않습니다. 필요한 날짜의 서명을 각각 취소합니다.
- 취소 기록이 있는 교육일·참여자에 대한 기존 기록 보호 규칙도 유지합니다. 보관/휴지통의 프로그램은 변경하지 못합니다.

## 검증

- `npm run check`: 일반 54개 + SQLite 6개 = 60개 통과, TypeScript/Vite 빌드 통과.
- 테스트: 이전 날짜·본인·프로그램 범위, QR 시간 범위, 권한, 마감, 원본 취소, 중복 재시도, 원본 파일 공유, 취소 후 재서명, 늦은 요청 차단, 오래된 취소 요청의 멱등성.
- SQLite 테스트: 불러오기 → PDF 생성 → 취소 → 새 PDF의 빈 서명 → 재서명. 이전 PDF의 이미지 및 원본 파일이 계속 유지됨을 확인합니다.
- 브라우저: 가상 4명과 고정된 2026-10-22 오전 시계의 독립 로컬 서버를 사용했습니다. 운영 저장소 및 기존 개발 데이터는 수정하지 않았습니다.
- 브라우저: QR 휴대폰 이름 선택 → 저장 서명 버튼 활성 → 클릭 → 완료, 관리자 취소 → 미서명 복귀 → QR에서 직접 서명 → 저장 완료 확인.
