# 파일 가져오기 집중 검증

- 일자: 2026-10-15
- 대상: 새 명단 생성 → 파일 첨부 → 시트·제목 행·열 선택 → 편집 → 저장
- 환경: 로컬 Vite·파일 저장 API와 브라우저. 실제 개인정보가 없는 검증용 명단 사용.

## 발견하여 수정한 문제

1. **BOM 없는 UTF-8 CSV 한글 깨짐:** CSV를 바이트 배열로 바로 읽던 방식을 수정했다. UTF-8을 명시적으로 해석하고 기존 한글 Excel CSV의 CP949, UTF-16 BOM도 처리한다. CSV의 숫자 자동 추론을 꺼 연락처 원문을 유지한다.
2. **빈 파일·가짜 Excel 파일 허용:** 빈 데이터, 실제 통합문서가 아닌 내용, 손상된 파일을 오류 안내와 함께 거절한다.
3. **공백·줄바꿈·필수 표시가 있는 열 제목 미인식:** 열 제목을 정규화하고 이름·연락처·비고 별칭을 보완했다. 보호자 연락처를 본인 연락처로 자동 연결하지 않는다.
4. **빈 첫 시트·뒤쪽 제목 행:** 이름·연락처 열이 있는 명단 시트를 우선 선택하며 실제 시트 행 번호를 유지한다. 20행 이후 제목 행도 선택할 수 있다.
5. **선택하지 않은 열만 채워진 잔여 행:** 선택한 명단 필드가 모두 비면 참여자로 만들지 않는다.
6. **열 중복 연결·범위 오류:** 이름·연락처·비고를 같은 열에 연결하거나 유효하지 않은 제목 행을 지정하면 화면에 오류를 표시한다.
7. **오류 복구:** 동일 파일 재선택, 미리보기의 ‘다른 파일 선택’, 업로드 중 이전 요청 결과가 덮어쓰는 문제를 방지했다. 파일 적용 전에는 생성 버튼을 비활성화한다.
8. **잘못된 연락처 안내 지연:** 가져오기 직후 수정이 필요한 행에 안내를 표시하고 수정 전 생성을 막는다.

## 자동 검증

파일 처리 테스트 20개, 기존 업무 규칙·권한 테스트 15개를 합해 **35개 통과**.

- XLSX/XLS/CSV/ODS 실제 파일 생성·파싱.
- UTF-8 BOM 있음/없음, CP949 CSV, UTF-16 CSV.
- 쉼표·줄바꿈이 있는 인용된 비고.
- 문자형 연락처, Excel 사용자 지정 표시 형식의 앞자리 0 보존.
- 이미 숫자로 저장되어 0이 사라진 연락처를 임의로 복원하지 않고 검증 오류 처리.
- 빈 파일·통합문서, 가짜 확장자·손상 파일.
- 제목 행 위치, B5에서 시작하는 시트의 실제 행·열 번호.
- 빈 첫 시트·안내 시트·명단 시트 자동 선택.
- 공백·줄바꿈·필수 기호 제목과 보호자 연락처 구분.
- 잘못된 열 연결, 빈 참여자 행 제외.
- 500명 허용·501명 거절, 5MB·2,000행·100열 제한.

## 브라우저 검증

| 사례 | 확인한 결과 |
|---|---|
| XLSX 복합 명단 | 빈 시트·안내를 건너뛰고 실제 명단 선택, 25행 제목 인식, 본인 연락처 열 연결, 명단 저장 |
| XLS 복합 명단 | 같은 시트·제목·열 연결 후 별도 명단 저장 |
| ODS 복합 명단 | 같은 시트·제목·열 연결 후 별도 명단 저장 |
| BOM 없는 UTF-8 CSV | 한글·전화번호·쉼표가 있는 비고를 보존한 채 저장 |
| 열 중복 선택 | 오류 안내 후 올바르게 다시 연결해 저장 |
| 빈 CSV·가짜 XLSX | 오류 안내, 생성 버튼 비활성화, 다른 파일 재선택 |
| 0이 없는 전화번호 | 가져오기 직후 해당 행 안내, 생성 시 차단, 직접 수정 시 행 오류 해제 |

## 검증 범위의 한계

- 제공된 실제 운영 파일이 없으므로 일반 파일과 위 예외 조건을 직접 만든 샘플로 시험했다. 모든 외부 파일에 오류가 없다고 보장하는 결과는 아니다.
- Google 스프레드시트는 XLSX/CSV 등으로 내려받은 파일을 첨부하는 방식이다. 스프레드시트 URL이나 `.gsheet` 바로가기 파일을 직접 연결하는 기능은 아니다.
- 암호화된 파일은 암호를 해제하고 가져와야 한다.
- Excel 원본에서 숫자형으로 저장되며 이미 사라진 앞자리 0은 추측해 복원하지 않는다. 가져오기 화면에서 원본 확인 후 수정해야 한다.
- 실제 Apps Script 배포 환경에서의 파일 도구 로딩·Sheets 저장은 계정 연결 후 추가 검증해야 한다. 이번 명단 저장 검증은 로컬 저장 어댑터 대상이다.

## 사용자 제공 파일 실물 검증 (2026-10-15)

- 대상: Downloads의 `통합 문서1.xlsx` (10,698바이트). 원본 변경 없음. 개인정보가 포함되어 테스트 픽스처나 문서에 원본 내용은 복사하지 않음.
- 로컬 웹앱의 실제 파일 선택 창으로 첨부. Sheet1, 제목 4행, 이름 2열, 전화번호 3열 자동 인식. 비고는 빈 값으로 가져옴.
- 30명 편집 명단 적용 → 생성 → 새로고침 → 명단 화면 30행(순번 1~30) 확인.
- 원본 XLSX XML과 로컬 저장 데이터를 대조해 이름·정규화 연락처·비고 30명 전부 일치. 전화번호 앞자리 0 보존. 브라우저 오류 로그 없음.
- 저장된 테스트 프로그램: `첨부파일 검증 · 통합 문서1`. 교육일은 임의로 지정하지 않음. 실제 Google 저장 검증은 아님.
- 발견·수정: 첫 파일 첨부 때 Vite가 지연 로드된 xlsx 의존성을 최적화하며 화면을 새로고침함. 개발 서버 optimizeDeps에 파서 의존성을 명시해 시작 시 준비하도록 수정. 서버 재시작 후 같은 파일로 생성 완료 확인.

## 파일 내부 제목 자동 입력 (2026-10-15)

- 파일명 자동 채움 제거. 열 이름 행 위의 첫 제목 후보를 프로그램명으로 사용. 병합 셀·빈 행·명시적인 프로그램명/값 행 지원. 부제는 붙이지 않음.
- 프로그램명을 비워두고 파일 단계로 이동 가능. 가져오기 단계에도 프로그램명 입력란을 제공해 인식 결과 확인·수정 가능. 제목 없는 파일은 직접 입력하며 빈 제목은 저장 차단. 시트/열 이름 행 변경 시 다시 탐색.
- 제공된 원본 파일을 실제 업로드해 최상단 제목 자동 입력과 30명 생성 성공 확인.
- 제목 없는 표·참여자명 오인 방지·작성일/안내 제외·상단 제목 선택 등 자동 테스트 추가. 총 40개 테스트 및 빌드 통과.
